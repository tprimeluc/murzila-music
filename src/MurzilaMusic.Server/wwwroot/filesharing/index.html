Murzila Filesharing — это хранилище твоих аудио, обложек и текстов с доступом по токену. Ссылки ведут на mursik-filesharing.cc.cd и работают в браузере, плеере и через API.

Что внутри

Не «облако вообще», а твой склад

Сервис не ищет файлы в интернете и не качает чужое. Он хранит ровно то, что загрузил владелец аккаунта.

Аудио

MP3, FLAC, WAV, OGG, M4A. Отдаётся с поддержкой Range, поэтому перемотка работает и в браузере, и в своём плеере.

Обложки

Обложка хранится рядом с треком и отдаётся отдельной ссылкой. Плеер подставляет её автоматически.

Тексты

Файлы .lrc прикрепляются к треку и не теряются при синхронизации между устройствами.

Доступ к файлам

Сначала получи токен на /api/token, потом дергай эндпоинты.

МетодПутьЧто делает
POST/api/tokenМеняет API-ключ на Bearer-токен
GET/api/music/libraryСписок твоих треков с размерами и ссылками
GET/api/music/files/{id}Аудиофайл, поддерживает Range
GET/api/music/cover/{id}Обложка трека
GET/api/music/track/{id}Метаданные одного трека
GET/api/healthПроверка, что сервер жив

Скачать файл

curl -L "https://mursik-filesharing.cc.cd/api/music/files/ID" \
  -H "Authorization: Bearer ТОКЕН" \
  -o track.mp3

Ссылка для <audio>

<audio controls
  src="/api/music/files/ID?token=ТОКЕН">
</audio>
Вопросы

Коротко о главном

Откуда берутся файлы?

Только из твоего аккаунта. Ты добавляешь треки в приложении — они попадают в твоё хранилище. Сервис не индексирует чужие каталоги и не качает музыку из интернета.

Почему ссылка без токена не открывается?

Это защита: файлы приватные. Токен можно передать заголовком Authorization: Bearer … или параметром ?token=… для плееров, которые не умеют заголовки.

Можно ли перематывать трек в браузере?

Да. Сервер отдаёт файл с поддержкой HTTP Range, поэтому браузер запрашивает нужный кусок, а не качает всё заново.

Нужен ключ?

Открой страницу API, войди в аккаунт и создай приложение — ключ покажется один раз и сразу превратится в токен.
