# Как сделать сервер доступным из другой страны и подключить входы

Это черновик инструкции. Основное правило не меняется: в облако попадают **только твои файлы**,
которые ты сам отметил для публикации. Чужие треки не скачиваются и не ищутся.

## 1. Почему трек не видно в США

Сервер слушает `http://localhost:5188` — это только твой компьютер. Чтобы открыть его из другой
страны, нужен публичный HTTPS-адрес. В beta 1.3 он встроен в клиент:

```text
https://murzila-music.shares.zrok.io
```

Пользователю не нужно ничего вводить: поля «Адрес сервера» в интерфейсе больше нет.
`MURZILA_SERVER_URL` осталась только для разработки и аварийного переключения, а привязку Kestrel
задаёт отдельная переменная `MURZILA_BIND_URL` (по умолчанию `http://localhost:5188`).

### Как поднять туннель с постоянным коротким адресом

Используется **zrok** — бесплатный сервис без карты, который позволяет закрепить имя навсегда.
Serveo, Cloudflare Quick Tunnel и localhost.run в этом проекте не работают стабильно.

1. CLI уже скачан в `C:\Tools\zrok\zrok2.exe`. Приглашение отправлено на `mursikt7@internet.ru`.
   Открой письмо, перейди по ссылке и скопируй токен.
2. Один раз включи окружение:
   ```powershell
   C:\Tools\zrok\zrok2.exe enable <ТОКЕН_ИЗ_ПИСЬМА>
   ```
3. Забронируй короткое имя (только один раз):
   ```powershell
   C:\Tools\zrok\zrok2.exe create name -n public murzila-music
   ```
4. Подними общий доступ:
   ```powershell
   C:\Tools\zrok\zrok2.exe share public localhost:5188 -n public:murzila-music --headless
   ```
   Адрес будет `https://murzila-music.shares.zrok.io`.
5. Проверь: `curl.exe https://murzila-music.shares.zrok.io/api/info`.

Или просто запусти `./scripts/start-online.ps1` — он сам поднимет сервер, имя и share,
а в случае остановки переподключит его (keepalive).

**Почему не Serveo/Cloudflare:** Serveo отклонял публичный ключ и не давал кастомное имя,
Cloudflare давал `502`/`530`, а localhost.run меняет домен при каждом перезапуске.

**Важно:** не задавай `MURZILA_ADMIN_TOKEN` как короткий пароль. Если сервер смотрит в интернет,
токен должен быть случайным (32 байта), а вход по почте — с подтверждением кода.

## 1.1. Перенос своих треков на другое устройство

Кнопка **«☁ Свои треки на других устройствах»** в левой панели синхронизирует только те файлы,
которые ты сам добавил и отметил как опубликованные. Чужие треки приложение не ищет и не скачивает.

1. Ничего настраивать не нужно — все клиенты подключаются к встроенному short URL
   `https://murzila-music.shares.zrok.io`. На сервере публичный адрес задан по умолчанию;
   при необходимости его можно переопределить только переменной `MURZILA_SERVER_URL`.
2. Войди в **один и тот же аккаунт** на обоих устройствах.
3. На устройстве-источнике нажми «Опубликовать» у нужных треков, затем кнопку синхронизации.
4. На втором устройстве войди в тот же аккаунт и нажми ту же кнопку — треки скачаются в локальную
   библиотеку. Обложка, видео и `.lrc` рядом с треком переносятся, если они есть.

Сервер хранит файлы только внутри своего аккаунта и отдаёт их только по токену этой сессии.
Если загруженный файл уже есть и размер совпадает, он пропускается — трафик не тратится зря.

## 2. SMS для номера телефона

Выбран провайдер **sms.ru** — оплата по факту, без абонентской платы, подходит для малого бюджета.
Одна SMS обычно стоит около 2–3 ₽, 30 ₽ хватит на десяток подтверждений.

1. Зарегистрируйся на https://sms.ru/ и пополни баланс.
2. В личном кабинете создай/скопируй API-ключ (`api_id`).
3. Перед запуском сервера:
   ```powershell
   $env:SMS_RU_API_ID = '...'
   ./scripts/start-server.ps1
   ```
4. Если ключ не задан, сервер работает в тестовом режиме: код подтверждения показывается
   прямо в окне приложения, реальные SMS не отправляются.

Номер в профиле показывается маскированным, например `+7 *** *** 12-34`.

## 3. Вход через Google — как получить ключи

1. Открой https://console.cloud.google.com/apis/credentials.
2. Создай проект (если нет) → «APIs & Services» → «Credentials».
3. «Create credentials» → «OAuth client ID» → тип **Web application**.
4. В «Authorized redirect URIs» добавь **ровно** тот адрес, который будет у сервера:
   - локально: `http://localhost:5188/api/auth/google/callback`
   - через туннель: `https://murzila-music.shares.zrok.io/api/auth/google/callback`
5. Скопируй **Client ID** и **Client secret**.
6. Задай до запуска сервера:
   ```powershell
   $env:GOOGLE_CLIENT_ID = '...'
   $env:GOOGLE_CLIENT_SECRET = '...'
   ./scripts/start-server.ps1
   ```
7. Проверка: `http://localhost:5188/api/info` должен показать `"googleConfigured": true`.

Если ключей нет, кнопка Google в окне входа теперь не молчит: она показывает понятную подсказку
и ссылку на эту инструкцию.

## 4. Письмо с кодом

SMTP уже настроен на `smtp.mail.ru:465` с неявным TLS. Письмо содержит крупный код,
подсказку «никому не сообщай» и подпись команды. В окне подтверждения есть кнопка копирования кода.
