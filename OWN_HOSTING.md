# Свой хостинг Murzila (вместо Render)

## Что уже сделано
- ASP.NET Core слушает `0.0.0.0:6001` (API/приложение) **и `0.0.0.0:80`** (публичный сайт без порта).
- Локальные адреса `localhost:6001` и `localhost:5188` сохранены — приложение и старые ссылки не сломаны.
- Один сервер отдаёт все сайты по `Host`:
  - `murzila-music.cc.cd` → плеер `/player`
  - `murzila-filesharing.cc.cd` → FileSharing `/files`
  - `mursik-corp.de5.net` → сайт компании
  - `/api/token`, `/download`, `/api/*` — на любом домене
- На Render привязка 80-го не добавляется (там переменная `PORT`), поэтому деплой в облако не сломан.

## Что нужно сделать вручную (DNS, my.dnshe.com)
Добавить/поправить A-записи на IP **`93.177.7.84`**:

| Имя | Тип | Значение | Статус |
|---|---|---|---|
| `murzila-music.cc.cd` (`@`) | A | `93.177.7.84` | **добавить** (сейчас нет записи) |
| `murzila-filesharing.cc.cd` | A | `93.177.7.84` | **добавить** (сейчас нет записи) |
| `mursik-corp.de5.net` | A | `93.177.7.84` | уже есть |
| `mursik-filesharing.cc.cd` | A | `192.168.1.58` | **оставляем как есть** — старый адрес работает как алиас, сервер отдаёт FileSharing по host-роутингу |

TTL поставь поменьше (300–600 сек), чтобы изменения быстро подхватились.

Оба домена `murzila-filesharing.cc.cd` и `mursik-filesharing.cc.cd` работают одновременно — роутинг смотрит на наличие `filesharing` в имени хоста, поэтому алиас можно оставить без изменений.

## Роутер
Порт **80 (TCP)** должен быть проброшен на `192.168.1.58`. Судя по тому, что `mursik-corp.de5.net` уже открывается снаружи, проброс настроен — дополнительно ничего делать не нужно. Если основной домен не откроется — проверь проброс 80-го.

## HTTPS
Сейчас сайты работают по `http://`. Варианты (по порядку простоты):
1. **Cloudflare** — пере delegated NS домена на Cloudflare, включить proxy (Flexible SSL). Сервер остаётся HTTP, пользователи получают HTTPS.
2. **win-acme + Let's Encrypt** — выпустить сертификат на 80-м порту (HTTP-01), положить PFX и добавить `app.Urls.Add("https://0.0.0.0:443")` с сертификатом.
3. Оставить HTTP, если это только тестовый хостинг.

## Проверка
```powershell
.\scripts\check-own-hosting.ps1
```
Скрипт показывает A-записи и отвечают ли сайты по HTTP.

## Переход с Render
1. Дождаться обновления DNS.
2. Убедиться, что `murzila-music.cc.cd/api/health` отвечает с нашего сервера (`version 3.9.0`).
3. Обновить `MURZILA_SERVER_URL` в `.env` бота и в настройках OAuth (Google/GitHub redirect URI) на новый адрес.
4. Render-сервис можно выключить/удалить только после проверки бэкенда, базы и OAuth на своём сервере.
